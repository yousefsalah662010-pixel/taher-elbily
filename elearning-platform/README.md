# منصة طاهر البيلي — منصة تعليمية إلكترونية متكاملة

تنفيذ عملي كامل لمقترح "تصميم وتطوير منصة تعليمية إلكترونية متكاملة" — واجهات عربية RTL بالكامل، بهوية بصرية عصرية (كحلي `#172554` / أزرق `#2563EB` / تركواز `#14B8A6`)، وضع ليلي ونهاري، وتصميم متجاوب لجميع الشاشات.

> **طبيعة النسخة الحالية:** واجهة أمامية ثابتة (Static) بـ HTML5 + CSS3 + JavaScript خالص بدون أي خطوة بناء (No build step). تعمل مباشرة بفتح الملفات في المتصفح، والبيانات تُحفظ في `localStorage` كقاعدة بيانات تجريبية تحاكي Backend حقيقي.

> **فصل كامل:** المشروع مكوّن من تطبيقين مستقلين كل منهما برابط ومجلد خاص به — **المنصة للطلاب** (`elearning-platform/`) و**لوحة تحكم الإدارة** (`elearning-admin/`). صفحات المنصة لا تحتوي أي رابط أو إحالة للوحة الإدارة، ورابط اللوحة يُوزَّع على فريق الإدارة فقط.

---

## 1) تشغيل المشروع

الطريقة الموصى بها: شغّل خادماً محلياً من **المجلد الأب** الذي يحتوي المجلدين معاً (حتى يعمل تبادل البيانات بين التطبيقين على نفس الأصل):

```bash
# من المجلد الأب الحاوي لـ elearning-platform و elearning-admin
python -m http.server 8080        # أو: npx serve .
```

ثم:

| التطبيق | الرابط |
|---|---|
| **المنصة (الطلاب)** | `http://localhost:8080/elearning-platform/` |
| **لوحة تحكم الإدارة** | `http://localhost:8080/elearning-admin/` |

- يمكن فتح `elearning-platform/index.html` مباشرة في المتصفح للتجربة السريعة، لكن **لتشغيل التطبيقين معاً وتبادل البيانات بينهما يُفضَّل الخادم المحلي** لأن البيانات (localStorage) مشتركة على مستوى نفس الدومين/المنفذ فقط.
- عند الاستضافة الحقيقية: ارفع المجلدين كما هما داخل نفس المجلد الجذري للموقع (web root) — ستعمل المنصة على `domain.com/elearning-platform/` ولوحة الإدارة على `domain.com/elearning-admin/`، ويمكن أيضاً ربط كل مجلد بدومين أو نطاق فرعي مستقل (مثل `admin.domain.com`) مع الحفاظ على نفس الأصل أو إعادة بناء طبقة البيانات على Backend (البند 4).

**حسابات الدخول:**

| الدور | البريد | كلمة المرور | مكان الدخول | ملاحظات |
|---|---|---|---|---|
| مدير عام | `taher-elbily@gmail.com` | `037754321` | رابط لوحة الإدارة | كل الصلاحيات |
| مشرف محتوى | `content@demo.com` | `content123` | رابط لوحة الإدارة | صلاحيات محدودة — إن لم تستخدمه فاحذفه أو غيّر كلمة مروره من `js/data.js` (قسم `admins`) لأنها معروفة |

**لا توجد حسابات طلاب تجريبية** — المنصة تبدأ فارغة تماماً: أول طالب يسجّل هو أول حساب. دخول الإدارة يتم **حصرياً من رابط لوحة الإدارة** (بوابة دخول خاصة بها) — صفحة تسجيل الدخول داخل المنصة مخصصة للطلاب فقط.

## 2) هيكل الملفات

```
المجلد الأب/
├── elearning-platform/        ← المنصة (واجهة الطلاب)
│   ├── index.html            الصفحة الرئيسية (10 أقسام كاملة)
│   ├── courses.html          صفحة الدورات (بحث + فلاتر + تفاصيل + اشتراك ودفع)
│   ├── lesson.html           صفحة مشاهدة الدروس (مشغل + قائمة + تقدم + نقاشات)
│   ├── login.html            تسجيل الدخول / حساب جديد (للطلاب فقط)
│   ├── dashboard.html        لوحة الطالب (8 أقسام)
│   ├── certificate.html      الشهادة القابلة للطباعة/PDF
│   ├── css/
│   │   ├── style.css         نظام التصميم الأساسي (الهوية، الوضع الليلي، التجاوب)
│   │   └── app.css           أنماط لوحات التحكم
│   └── js/
│       ├── icons.js          مكتبة أيقونات SVG مدمجة (بدون مكتبات خارجية)
│       ├── data.js           طبقة البيانات + البيانات الأولية + منطق المنصة
│       ├── ui.js             مكونات مشتركة (سمة، نوافذ، توست، هيدر...)
│       ├── charts.js         رسوم بيانية SVG خفيفة (أعمدة/خطي/دائري)
│       ├── main.js           منطق الصفحة الرئيسية
│       ├── courses.js        منطق صفحة الدورات
│       ├── lesson.js         منطق صفحة الدروس
│       ├── auth.js           منطق الدخول والتسجيل (الطلاب)
│       └── dashboard.js      منطق لوحة الطالب
│
└── elearning-admin/           ← لوحة تحكم الإدارة (مستقلة تماماً)
    ├── index.html            اللوحة (8 أقسام) + بوابة دخول المديرين
    ├── css/                  نسخة ذاتية من أنماط التصميم (style.css + app.css)
    └── js/
        ├── icons.js          أيقونات SVG
        ├── data.js           نفس طبقة البيانات (تقرأ/تكتب نفس قاعدة localStorage)
        ├── ui.js             مكونات مشتركة
        ├── charts.js         رسوم بيانية للوحة التحكم
        ├── admin.js          النواة + نظرة عامة + الطلاب (بما فيها حذف الطالب نهائياً) + الدورات + بوابة الدخول
        └── admin-extra.js    المالية + الاختبارات + المحتوى + الدعم + الصلاحيات
```

ملاحظتان عن الفصل:
- مجلد اللوحة **ذاتي الاكتفاء (self-contained)**: يحمل نسخته الخاصة من CSS وJS، ويعمل حتى لو نُقل أو استُضاف وحده (في هذه الحالة يحتاج طبقة بيانات backend مشتركة — انظر البند 4).
- أي تعديل مستقبلي على منطق البيانات في `js/data.js` يُطبَّق على النسختين (في المنصة وفي اللوحة) حتى يظلا متطابقين.

## 3) تغطية متطلبات المقترح

**الواجهة العامة:** هيدر احترافي، Hero، دورات مميزة، المميزات، طريقة الاستخدام (4 خطوات)، آراء الطلاب، إحصائيات بعدّاد متحرك، مقالات، أسئلة شائعة، CTA، فوتر شامل — بالإضافة لشريط إعلانات يديره المشرف.

**حساب الطالب:** إنشاء حساب/دخول، تعديل البيانات وكلمة المرور، استعراض واشتراك الدورات، مشاهدة الدروس مع حفظ التقدم تلقائياً (وعند انتهاء الفيديو)، نسبة تقدم لكل دورة، اختبارات بدرجات ونتائج فورية، شهادات إتمام قابلة للطباعة، سجل اشتراكات، إشعارات، ودعم فني برسائل متبادلة.

**لوحة الإدارة (8 أقسام):**
1. **نظرة عامة:** بطاقات إحصائية + رسم أعمدة للإيرادات (6 أشهر) + دائري لتوزيع الاشتراكات + خطي للتسجيلات (14 يوم) + أحدث التسجيلات والأنشطة.
2. **الطلاب:** بحث، ملف شخصي كامل بالتقدم، تفعيل/إيقاف، تعديل، **حذف الطالب نهائياً** (زر الحذف مع نافذة تأكيد توضح كل ما سيُحذف: الاشتراكات ونتائج الاختبارات وعمليات الدفع والرسائل والأسئلة والإشعارات).
3. **الدورات:** إضافة/تعديل/نشر/إلغاء نشر/أرشفة/حذف + مدير دروس كامل (ترتيب، مدة، رابط فيديو، مرفقات).
4. **الاشتراكات والمدفوعات:** تأكيد/رفض الدفعات المعلقة، سجل معاملات، إيرادات الشهر، **تصدير CSV**.
5. **الاختبارات:** إنشاء أسئلة بخيارات وتحديد الإجابة الصحيحة ودرجة النجاح، نتائج الطلاب وتقارير أداء (محاولات/متوسط/نسبة نجاح).
6. **المحتوى:** تعديل نصوص الصفحة الرئيسية والإحصائيات وبيانات التواصل، إدارة الإعلانات والأسئلة الشائعة والأخبار.
7. **الدعم الفني:** صندوق الرسائل، الرد (يصل الطالب كإشعار)، تغيير الحالة، الأرشفة.
8. **الصلاحيات والأمان:** حسابات مشرفين بصلاحيات مستقلة لكل قسم، سجل العمليات الإدارية، تغيير كلمات المرور، حماية الأقسام من غير المصرح لهم.

## 4) طبقة البيانات والترقية لاحقاً

كل القراءة والكتابة تمر عبر دوال موحدة في `js/data.js` (`enroll`, `confirmPayment`, `markLessonDone`, `submitQuiz`, `deleteStudent`, `addNotification`, `logActivity`...). للترقية إلى **Firebase** أو Backend مخصص: استبدل تنفيذ هذه الدوال فقط (بدلاً من localStorage استخدم Firestore/REST) دون لمس أي ملف واجهات — وعندها يصبح التطبيقان قادرين على العمل على نطاقين منفصلين تماماً لأن البيانات ستأتي من الخادم وليس من المتصفح.

**ملاحظات مهمة:**
- البيانات مشتركة بين كل صفحات التطبيقين على نفس المتصفح ونفس الأصل (الدومين/المنفذ) — هذا هو الربط بين المنصة ولوحة الإدارة. لإعادة تعيين التجربة: زر "إعادة تعيين البيانات" في قسم الأمان بلوحة الإدارة، أو امسح بيانات الموقع من المتصفح.
- كلمات المرور محفوظة نصاً في النسخة التجريبية فقط — في الإنتاج تُستخدم مصادقة حقيقية مع تشفير (مثل Firebase Auth).
- المدفوعات محاكاة فقط: أي "دفع" ينشئ طلباً معلقاً يؤكده المشرف من قسم المالية.
- الفيديوهات التجريبية من مصدر عام على الإنترنت (تحتاج اتصالاً) — استبدل روابطها من قسم "إدارة الدروس" بلوحة الإدارة.
- العملة الافتراضية: الجنيه المصري (ج.م) — يمكن تغييرها من `js/data.js` (دالة `fmtPrice`).

## 5) الخطوات المقترحة قادماً

تطبيق جوال (PWA أولاً)، تحقق من الشهادات برمز QR، فصول افتراضية مباشرة، مسارات تعليمية مترابطة، وربط بوابة دفع حقيقية.
